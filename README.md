# DevolutionsCrypto
This repo contains the library used for cryptography of products used by Devolutions. 
It also includes wrappers for it in different languages.  
Currently, the supported languages are: [Rust](src/), [C#](wrappers/csharp/) and [Javascript/Typescript](wrappers/wasm/), [Kotlin](wrappers/kotlin), [Swift](wrappers/swift/)

Python bindings are also available. You can install it with `pip3 install devolutions-crypto`, but this might not work depending on the platform. If it doesn't, you can try building it manually.

Note that the Javascript version of the library is compiled using WebAssembly, so it can run in a browser.

# Underlying algorithms
As of the current version:
 * Symmetric cryptography uses XChaCha20Poly1305
 * Asymmetric cryptography uses Curve25519
 * Asymmetric encryption uses ECIES.
 * Key exchange uses x25519, or ECDH over Curve25519
 * Key derivation uses Argon2id or PBKDF2-HMAC-SHA2-256
 * Password Hashing uses PBKDF2-HMAC-SHA2-256
 * Secret Sharing uses Shamir Secret sharing over GF256
 * Online Ciphertext uses XChaCha20-Poly1305

# FIPS mode
The library can be built with a `fips` feature that adds a version 3 of every data type except Online Ciphertext and Secret Sharing, backed by the [AWS-LC](https://github.com/aws/aws-lc) FIPS 140-3 validated module through [aws-lc-rs](https://github.com/aws/aws-lc-rs):

| Data type                  | V3 algorithm                                                                          |
|----------------------------|---------------------------------------------------------------------------------------|
| Ciphertext (symmetric)     | AES-256-GCM (IV generated by the module), key derived per message with HKDF-SHA256    |
| Ciphertext (asymmetric)    | Ephemeral-static ECDH over NIST P-256, then the symmetric V3 construction             |
| Key                        | NIST P-256 keypairs and ECDH key exchange                                             |
| SecretKey                  | 32 bytes from the module's DRBG                                                       |
| SigningKey / Signature     | ECDSA over NIST P-256 with SHA-256                                                    |
| PasswordHash / KeyDerivation | PBKDF2-HMAC-SHA256 (salt of at least 16 bytes, at least 1000 iterations)            |

With the feature enabled:
 * `Latest` resolves to V3. Without it, `Latest` still resolves to the previous versions.
 * All randomness comes from the module's DRBG.
 * Encryption, password hashing, key derivation, online encryption and secret sharing refuse to produce data with the older, non-approved versions and return `NotFipsApproved` (error code -45). `derive_key_pbkdf2` and `scrypt_simple` are not available.
 * Data produced with the older versions can still be decrypted, verified and joined, so it can be migrated.
 * `fips::ensure_fips_mode()` (Rust), `EnsureFipsMode()` (FFI), `ensure_fips_mode()` (UniFFI) and `Utils.IsFipsMode()` (C#) check that the module runs in FIPS mode.

The feature is available for the Rust crate, the FFI (`devolutions-crypto-ffi`) and the UniFFI bindings (`devolutions-crypto-uniffi`). For .NET, the `Devolutions.Crypto.Core.Fips` NuGet package ships the FIPS native libraries for Windows x64, Linux x64/arm64 and macOS x64/arm64. It is not available for WebAssembly.

On Windows and macOS, the FIPS module is a separate shared library (`aws_lc_fips_<version>_crypto.dll` / `libaws_lc_fips_<version>_crypto.dylib`) that must ship next to the native library. On Linux, it is linked statically.

# Devolutions Crypto Header

### Example Header 
| Position  | Byte value  |
|-----------|-------------|
|  1        |       0xD   |
|  2        |       0xC   |
|  3        |       0x1   |
|  4        |       0x0   |
|  5        |       0x1   |
|  6        |       0x0   |
|  7        |       0x1   |
|  8        |       0x0   |

This header represents : 
A Curve25519 private key from Devolutions Crypto

- Signature Bytes
  -  The first two bytes specifies that the data is from Devolutions Crypto (DC) 
- Data type
  - The second two bytes (pos: 3,4 ) represents the data type.
- Data sub type
  - The third two bytes (pos: 5, 6) represents the data sub type.
- Version
  - The fourth two bytes (pos: 7, 8) represents the version.

## Data Type

| Data Types          | Value  |  Description                                                                 |
|---------------------|--------|------------------------------------------------------------------------------|
|  None               |  0x00  | No data type. Only used as a default value.                                  |
|  Key                |  0x10  | A wrapped key.                                                               |
|  Ciphertext         |  0x20  | A wrapped ciphertext. Can be either symmetric or asymmetric.                 |
|  PasswordHash       |  0x30  | A wrapped password hash. Used to verify a password.                          |
|  Share              |  0x40  | A wrapped share. Used for secret sharing scheme.                             |
|  SigningKey         |  0x50  | A wrapped key used to sign data.                                             |
|  Signature          |  0x60  | A wrapped signature.                                                         |
|  OnlineCiphertext   |  0x70  | A wrapped online ciphertext that can be encrypted/decrypted chunk by chunk   |
|  KeyDerivation      |  0x80  | Serialized key derivation parameters used to reproduce a derived secret key. |

# Local development setup

## Rust

Build the project with cargo.

```
cargo build
cargo test
```

## FIPS

The AWS-LC FIPS module is built from source, which requires CMake, Go and libclang (LLVM). On Windows, it also requires [NASM](https://www.nasm.us/), and the build must run in a Visual Studio developer environment (`vcvars64.bat`) so that libclang finds the C runtime headers.

```
cargo build --features fips
cargo test --features fips
```

The same feature exists on `devolutions-crypto-ffi` and `devolutions-crypto-uniffi`. To run the C# FIPS tests (`TestFips`), build the FFI with `cargo build -p devolutions-crypto-ffi --features fips` first: the test project copies the FIPS module DLL next to the native library.

## C#

Build the rust library, then open the solution wrappers\csharp\tests\unit-tests\local\devolutions-crypto-tests\devolutions-crypto-tests.sln.

## WebAssembly

**Setup**

- Install the wasm32-unknown-unknown target with `rustup target add wasm32-unknown-unknown`
- Install `wasm-pack` with `cargo install wasm-pack`.

**Building**

Run `wasm_build.ps1` or `wasm_build.sh` in the wrappers/wasm folder.

Tests can then be run in the wrappers/wasm/tests folder.

```
npm install
npm run test
```
